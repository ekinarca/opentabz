# Security policy

OpenTabz runs entirely in your browser: there is no server that receives your files, no account
and no analytics. The attack surface is therefore the files you open (parsers), the URLs you
choose to open, and the app's own static assets.

## Supported versions

Only the version deployed at [opentabz.com](https://opentabz.com) and the latest commit on `main`
receive security fixes.

## Reporting a vulnerability

Please report vulnerabilities **privately** through GitHub's
["Report a vulnerability"](https://github.com/ekinarca/opentabz/security/advisories/new) form.
Do not open a public issue.

Helpful details:

- what an attacker can achieve (for example script execution from a crafted file, data leaving
  the device, denial of service that survives a reload);
- a minimal reproduction — a crafted file you made yourself, never a copyrighted song;
- browser, version and operating system.

You will get an acknowledgement within 7 days. Fixes for confirmed issues are prioritised over
feature work, and reporters are credited in the changelog unless they prefer otherwise.

## Hardening in place

- Strict Content-Security-Policy: scripts, workers, fonts and styles only from the app's own
  origin; no third-party origins; `object-src 'none'`; `frame-ancestors 'none'`.
- Cross-origin isolation (COOP/COEP) and `Referrer-Policy: no-referrer`.
- All file parsing happens in a dedicated worker with a watchdog; a malformed file can at worst
  stall that worker, which is then terminated and restarted.
- Rendered notation is generated by the engine from parsed data; text from files is escaped by
  the renderer before it reaches the DOM.
